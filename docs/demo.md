# Five-minute judge walkthrough

Before presenting, follow the [setup instructions](../README.md#run-locally), keep both the API and Vite terminals running, and check `/api/health`. For a deployed demo, verify the same routes on its HTTPS origin. A guest demo needs no account or database setup. Account synchronization on Vercel requires PostgreSQL configuration.

1. Explain the bridge: Quantum Grove connects a prediction, a simulation, and a spatial representation. Open the machine-learning crystal and choose **Set as my learning goal**. Switch to **Full course catalog → Show optional branches** to show optimization alongside the required foundations.
2. Complete the first mathematics quiz. Show the 25 XP reward and refresh to demonstrate browser-saved guest progress. New lessons in later courses require prerequisite completion; the public labs remain open.
3. In Quantum lab, reset, apply H, then H. Explain why the final Z-basis measurement is certain. Reset, apply H then S, and explain the equal probabilities with a changed relative phase. Run with Qiskit to compare the exact state with sampled counts.
4. Run Bell and discuss correlated counts and a mixed individual qubit. Choose one further example: Grover's phase oracle/diffusion, the QFT's complex amplitudes, or QAOA's manual cost-angle sweep. The variational energy experiment compares a trial state with a toy spin ground energy; it is not an H₂ calculation.
5. Answer a daily fun-fact question and reveal its explanation. The three-question quiz builds a participation streak separately from course XP. Signing in is optional.
6. Choose **Immersive lab → Open local 3D lab** for desktop orbit and gate controls. The separate **Launch on Meta Quest** action opens an external hosted experience. Local headset entry needs a compatible WebXR browser and a secure context. Physical headset use and native Unity compilation remain unverified; use the [Unity guide](../apps/unity/README.md) for that separate setup.

Keep additional algorithm experiments and the account demonstration as follow-ups if the five-minute slot is tight. For an account demonstration, explicitly import guest lesson completions, save a new lesson, and sign in from another browser to show persistence. Guest daily history is not included in that import. Sign out afterward to demonstrate returning to the original guest history.

## Notebook

[judge_demo.ipynb](../notebooks/judge_demo.ipynb) contains executable ideal Qiskit examples for H/HH, Bell states, Grover, QFT, a QAOA sweep, and the variational toy Hamiltonian. Its code uses the locked API dependencies and does not need the HTTP server. The cells should run in order in the project's Python environment.

For a notebook UI, use a Jupyter-compatible editor and select `.venv` as its kernel. If the editor needs a kernel package, install `ipykernel` into that environment using `.venv/bin/python -m pip install ipykernel` on macOS/Linux or `.\.venv\Scripts\python.exe -m pip install ipykernel` in PowerShell. Notebook UI/kernel tooling is optional and is not included in the API runtime dependencies.

The notebook is generated by `scripts/create_notebook.py`. Regenerate it with the same environment's Python interpreter after editing that script; generated cells have stable format-required IDs and no saved execution outputs. Regeneration alone does not execute or validate the cells.

The root [embedded demo notebook](../Qubit_Quest_Fall_Fest_2026_Embedded_Demo.ipynb) adds an iframe of the configured live site and source links to the same Qiskit examples. It needs an IPython/Jupyter kernel for the HTML display cell. The iframe requires internet access and may be blocked by notebook or site security policy; use its full-screen link in that case. Its hosted URL and team-repository links are external references, not a guarantee that the deployment matches this fork. The historical filename is retained.

The repository supplies a demo notebook. Event registration, presentation slides, and submission are separate team tasks; confirm the current requirements with the organizers.

Be ready to explain Born's rule, relative phase, bit ordering, oracle assumptions, QAOA angles, variational bounds, and why simulation is not a demonstration of practical quantum advantage.
